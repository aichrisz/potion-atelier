## Core simulation and exact scoring
DOM-free deterministic engine, seeded/injected random permitted; explicit seconds delta independent of render frame count. Separate phase ready/running/paused/results and stage ingredients/heating/stirring/bottled. Invalid actions are rejected atomically with a reason, no money/stat/stage mutation. Snapshot/profile copies detached; recipe/ingredient tables immutable.

During ingredients, tap/click or keyboard-activate native ingredient buttons to toggle unique ingredients, max3. Reset brew removes ingredients/heat/stir/pending bottle without money penalty. Primary action begins heating only with exactly3. Heating starts temperature20, fire60. Native range0..100 controls FIRE, not fake temperature; actual temperature evolves over active time. Use exact Newton update: equilibrium=20+1.6*fire; temp=clamp(20,100,equilibrium+(temp-equilibrium)*exp(-0.1*dt)). Maintain heatElapsed. After >=1active second, primary action lifts the pot, captures actual temperature and starts stirring. No continued heating after that.

Stir needle sweeps a real triangular wave0..100..0 with period2.4active seconds, starting0. After>=0.25active seconds, primary action bottles using the current needle position. Essential needle and temperature evolution remain active with reduced motion; rain/bubbles/sway are decorative only. Show target bands AND numeric/text instructions so information is not color-only.

Quality calculation: ingredient points60 iff exact required set, otherwise0. Heat points=max(0,20-distance from captured temperature to recipe heat band). Stir points=max(0,20-0.8*distance from needle percent to recipe stir band). Inside a band's inclusive edges distance0. quality=round(sum), clamped0..100. Coin reward=0 if quality<50 else round(basePrice*(quality/100)^2). Reputation starts50 for a new profile; delta+3 if quality>=85, +1 if>=50, else-4, clamp0..100. All coins/counts integer/nonnegative; no floating negative resources.

Bottled stage shows actual quality breakdown/reward before a separate primary “Serahkan ramuan” action. Serving credits exactly once, increments served and good(quality>=50), quality total/best, updates reputation, consumes that order and resets brew for the next actual customer. Double activation cannot serve twice or fabricate rewards. Merely bottling/resetting never credits coins. Wrong ingredient mixture can be completed but scores at most40 and pays0, with honest feedback.

step(dt) advances exactly min(dt,timeRemaining) only while running, including correct heat/needle evolution for large dt. Finish at180active seconds once: no post-time cooking or serving; unfinished brew is not auto-paid. Finish increments profile completedShifts exactly once, totalCoins/bestShiftCoins/bestQuality/reputation from actual served stats. Repeated renders/step/results activation never re-award progression. startShift preserves completed profile but resets all active stats/stages/time; resetBrew never resets the shift clock.

Suggested exact engine API (keep it coherent): Potion.Engine.create({seed,profile})→startShift(),pause(),resume(),step(seconds),toggleIngredient(id),resetBrew(),setHeat(power),advance(),snapshot(),profile(). advance returns accepted/reason/event; snapshot includes phase,stage,remaining,order,ingredients,temperature,fire,heatElapsed,stirElapsed,stirPosition,potion,coins,served,good,qualityTotal,bestQuality,reputation and derived unlockedCount/averageQuality as appropriate. Export the same real engine through CommonJS for Node tests and a single browser namespace for UI. Do not expose a mutable live-game test hook or query-mode cheat.
